# AGENTS.md — инструкции для агентов разработки CPM v3

CPM v3 — WordPress-плагин управления проектами (аналог Basecamp). Проект ведётся агентами (opencode, Cursor). **Начни с чтения этого файла и `docs/README.md`.**

## Карта проекта

| Путь | Что это |
| ---- | ------- |
| `source/` | **Весь программный код плагина** (папка плагина = `CPM_PLUGIN_DIR`) |
| `source/cpm.php` | Главный файл плагина |
| `source/classes/` | Классы плагина (по карте `docs/01-классы.md`) |
| `source/extensions/` | Расширения и их менеджер |
| `docs/` | **Спецификации** (перенос из Obsidian). Обязательны к прочтению перед работой над любым модулем |
| `docs/core/` | Спецификации ядра: классы, права, SQL, хуки, кэш, ошибки, открытые вопросы |
| `tests/` | Стратегия и спецификации тестирования (два уровня), скаффолд PHPUnit |
| `sql/` | Сервисные SQL-скрипты для отладки (в коде не используются) |

## Как работать

1. **Сначала спецификация.** Перед реализацией/изменением класса прочитай его документ в `docs/` (например, `docs/core/task.md` для Task). Не выдумывай поведение — следуй спецификации.
2. **Открытые вопросы** — в `docs/core/открытые-вопросы.md`. Если решение не зафиксировано, не додумывай молча: либо следуй «принятым решениям», либо спроси.
3. **Тесты вместе с кодом.** Для каждого класса добавляй тесты по матрице `tests/покрытие.md`. Конвенции — `tests/стандарты-тестов.md`, конфигурация — `tests/конфигурация.md`.
4. **Загрузка классов** — только через `require()` (менеджеры модулей), никакого автозагрузчика.

## Ключевые конвенции (сводка)

- Пространства имён: базовое `\CPM\v3\`, ядро `\CPM\v3\Core\`, REST `\CPM\v3\REST\`, UI `\CPM\v3\UI\`, расширения `\CPM\v3\Extensions\`.
- Данные — только CPT + `postmeta`, без собственных таблиц (кроме чтения легаси `in_cpm_user_role`).
- SQL в документации — прототипы. В коде: `$wpdb->prepare()`, `$wpdb->posts`/`$wpdb->postmeta`, динамический фильтр `is_admin OR team LIKE ...`.
- Единые имена: `get_wp_args()`, `load_list()`, константа `CPT` (не `get_args`/`get_list`/`CTP`).
- Логирование: только `\CPM\v3\Plugin::get_instance()->log($msg, $level)`. Уровень `debug` — удалять перед релизом.
- Права: `ACL::get_role()`, декораторы с `can_modify()`; запрет → `AccessDeniedException` (не no-op).
- Без автозагрузчика: классы подключаются через `require()`.

## Проверка перед сдачей

- `php -l` на каждом изменённом PHP-файле.
- Юнит-тесты: `vendor/bin/phpunit`.
- Интеграционные (на стенде в Docker, тестовая БД `cpm_test`): `vendor/bin/phpunit -c phpunit-integration.xml.dist`.

## Git

- Рабочая ветка — `v3`.
- Коммит только по явному запросу пользователя. В коммит не должны попадать секреты и `.env`.

## Приоритет разработки

Текущий статус: реализация ядра не начата (есть только каркас менеджеров). Следующий шаг — сущности ядра по `docs/core/` (от `Entity` к конкретным классам), затем ACL/декораторы, затем `load_list()`/`create()` в `Core_Manager`.
