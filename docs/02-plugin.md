# Класс Plugin

Класс `\CPM\v3\Plugin` инициализирует всю систему и её модули, создавая экземпляры классов менеджеров модулей.

## Структура класса

| Свойство | Тип | Назначение |
| -------- | --- | ---------- |
| `CPM_PLUGIN_DIR` | string | Путь к папке плагина |
| `CPM_PLUGIN_URL` | string | URL к папке плагина для служебных целей |
| `settings` | Settings | Экземпляр класса Settings |
| `core` | Core_Manager | Экземпляр менеджера ядра |
| `rest_api` | REST_API_Manager | Экземпляр менеджера REST API |
| `ui` | UI_Manager | Экземпляр менеджера UI |
| `extensions` | Extensions_Manager | Экземпляр менеджера расширений |

| Метод | Сигнатура | Назначение |
| ----- | --------- | ---------- |
| `get_instance()` | static : Plugin | Возвращает экземпляр Plugin (синглтон) |
| конструктор | `__construct($plugin_folder, $plugin_url)` | Сохраняет путь и URL |
| `init()` | `: void` | Создаёт экземпляры менеджеров модулей |
| `log()` | `($message, $level = 'info') : void` | Централизованное логирование |

## Инициализация

В основном файле плагина класс инициализируется следующим образом:

```php
new \CPM\v3\Plugin(
	plugin_dir_path( __FILE__ ),  // Путь к папке
	plugin_dir_url( __FILE__ )    // URL плагина для служебных целей
);
```

Значения, полученные конструктором, сохраняются в свойствах `CPM_PLUGIN_DIR` и `CPM_PLUGIN_URL` (хотя они записаны как константы, это свойства).

## Класс-синглтон

Класс реализован как синглтон со статическим методом `get_instance()`, чтобы в любом месте кода быстро получить доступ к любому свойству Plugin:

```php
\CPM\v3\Plugin::get_instance()->settings->some_method();
$my_path = \CPM\v3\Plugin::get_instance()->CPM_PLUGIN_DIR;
```

## Инициализация модулей

Свойства `core`, `rest_api`, `ui`, `extensions` содержат экземпляры менеджеров модулей, создаваемые по хуку `init`. В конструкторе устанавливается хук:

```php
add_action( 'init', array( $this, 'init' ) );
```

В методе `init()` создаются экземпляры менеджеров:

```php
public function init() {
	$this->core       = new Core_Manager();
	$this->rest_api   = new REST_API_Manager();
	$this->ui         = new UI_Manager();
	$this->extensions = new Extensions_Manager();
}
```

Такой подход гарантирует, что конструкторы менеджеров вызываются по хуку `init`; в самих менеджерах не требуется отдельная реализация хука `init` — их конструкторы выполняют роль инициализации.

## Логирование

Метод `log()` — централизованное логирование во всей системе. Запись в лог везде выполняется так:

```php
\CPM\v3\Plugin::get_instance()->log( 'Сообщение об ошибке', 'error' );
```

Уровни сообщений:

- `error` — ошибки, приводящие к невозможности работы.
- `warn` — предупреждения и ошибки, не приводящие к остановке работы.
- `info` — информационные сообщения.
- `debug` — отладочные сообщения; **должны быть удалены из кода перед релизом**. Для отладки пользоваться именно этим уровнем.

Реализация максимально простая:

```php
public function log( $message, $level = 'info' ) {
	// Если режим отладки выключен, ничего не логируем
	if ( ! WP_DEBUG ) {
		return;
	}
	// Запись в стандартный лог ошибок WordPress
	error_log( '[' . date( 'd.m.Y H:i:s' ) . '] CPM: ' . $level . ': ' . $message );
}
```
