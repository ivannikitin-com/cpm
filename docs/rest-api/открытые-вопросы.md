# Открытые вопросы и принятые решения модуля REST API

Реестр открытых вопросов модуля REST API. Часть вопросов пересекается с ядром (`docs/core/открытые-вопросы.md`) — REST-слой не должен принимать решения за ядро.

## Принятые решения (зафиксировано)

| № | Тема | Решение |
| -- | ---- | ------- |
| 1 | Namespace маршрутов | `cpm/v1` (`README.md`) |
| 2 | Права | Только через ядро; контроллер не проверяет права сам (`права-и-ошибки.md`) |
| 3 | Список/одна сущность | Через `load_list()`; одна сущность = фильтр `id` |
| 4 | Недоступная сущность | Возвращается как `404` (не раскрываем факт существования) |
| 5 | Запрет модификации | `403` `cpm_forbidden` |
| 6 | Бинарный файл вложения | `GET /attachment/{id}/file`, а не `GET /attachment/{id}` (метаданные JSON отдельно) — расходится с прототипом `docs/core/attachment.md`, см. `маршруты.md` |
| 7 | Аутентификация | Только штатные механизмы WordPress REST (cookie+nonce, application passwords) |
| 8 | Ленивая загрузка контроллеров | `require()` по хуку `rest_api_init` |
| 9 | Имена полей в JSON | = свойства сущностей ядра (snake_case) |
| 10 | Команда в ответах | `{user_id: role}`, без подгрузки данных пользователей |
| 11 | Иерархия контроллеров | Принято: общий `Entity_Controller` (abstract) + конкретные контроллеры по типам; конкретные минимальны (`архитектура.md`) |
| 12 | База контроллеров | Контроллеры **наследуют штатный `WP_REST_Controller`** (не собственная тонкая база) |
| 13 | Контроллер пользователей | Отдельный `/cpm/v1/user` **не создаётся**: там, где можно, используется штатный WP REST. Вопрос имён/аватаров участников остаётся на уровне ядра/UI (`аутентификация.md`, `открытые-вопросы.md` ниже) |
| 14 | Пагинация | Включается; требует доработки ядра (`LIMIT`/счётчик в `load_list()`). Заголовки `X-WP-Total` / `X-WP-TotalPages` — **включаем** |
| 15 | Сортировка | `orderby`/`order` поддерживается; требует доработки ядра (`load_list()`) |
| 16 | Даты в JSON | Формат хранения ядра (`Y-m-d H:i:s`), без конвертации в ISO 8601 — фиксируется в `схемы.md` |
| 17 | Неизвестные поля в теле | `400 Bad Request` |
| 18 | Read-only поля в теле | `400 Bad Request` |
| 19 | Тексты ошибок | Человекочитаемые, внятные (`права-и-ошибки.md`) |
| 20 | Изменение `team` | **Отдельный маршрут-экшен**, не общий update (`маршруты.md`) |
| 21 | Обёртки ядра (`archive()`, `unarchive()`, `set_coordinator()`, `set_thumbnail()`) | **Отдельные маршруты-экшены**, не поля общего update (`маршруты.md`) |
| 22 | `team` у задач/списков (исполнители) | Те же правила, что у проекта |
| 23 | Удаление: формат ответа | `204 No Content` |
| 24 | API-ключ внешних сервисов | Не вводится. Аутентификация — штатный WordPress; авторизация — контроллер по ACL/декораторам ядра. «Ключ» (пароль приложения) задаётся штатными средствами WP (`аутентификация.md`) |
| 25 | Discovery-схема | Регистрируется **в полной мере** через `get_item_schema()` (каталог `/wp-json/`) |
| 26 | Activity: фильтры списка и SQL | Вопрос ядра — решение фиксируется в `docs/core/activity.md` (см. ниже) |
| 27 | Загрузка файла в ядре | Механизм реализован: `Attachment::validate_upload()` / `Attachment::create_from_upload()` (`docs/core/attachment.md`); REST-контроллер принимает multipart и вызывает его |

## Открытые вопросы

### Пользователи (ядро/UI)

- [ ] Имена/аватары участников проекта для UI. Решение №13: отдельного REST-контроллера пользователей нет; штатный WP REST (`/wp/v2/users`) требует право `list_users`, которого у ролей CPM (client/co_worker) обычно нет. Вопрос остаётся на уровне ядра/UI — см. `аутентификация.md`.

### Вложения (пересекается с ядром)

Механизм загрузки в ядре реализован (`Attachment::validate_upload()`/`create_from_upload()`, whitelist `cpm_allowed_mime_types`, лимит `cpm_max_upload_size`, привязки `_project`/`_parent`/`commentmeta._files`). Осталось по REST:

- [ ] Параметр `size` миниатюры и заголовки download при отдаче файла (маршрут `/attachment/{id}/file`).

### Комментарии и активность

- [x] `comment`: точный набор свойств и чтение через ядро — **решено** в ядре (`docs/core/comment.md`: `query_rows()`/`query_count()`, пагинация/сортировка).
- [x] `activity`: точный набор хуков — **решено** в ядре (`docs/core/activity.md`). Фильтры списка и SQL чтения лога закрыты (решение №26).

### Точные тексты ошибок

- [ ] Финальные русские тексты `code`/`message` для всех ошибок (`права-и-ошибки.md`) — решение принято (№19), тексты фиксируются при реализации.
