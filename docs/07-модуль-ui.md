# Модуль UI

> Спецификация минимальна: модуль заявлен в архитектуре, детали не описаны отдельным документом. Ниже зафиксировано всё известное.

## Ключевое решение

- Интерфейс CPM делается на **React**, и он **единый**.
- **На бэкенде интерфейса нет**: только настройки и отладочные страницы. Весь UI работает через REST API (`docs/06-модуль-rest-api.md`).

## Место в архитектуре

- Менеджер модуля: `\CPM\v3\UI\UI_Manager`, файл `CPM_PLUGIN_DIR/classes/ui/ui_manager.php`.
- Создаётся в классе `Plugin` по хуку `init`.
- Классы UI загружаются только при рендеринге интерфейса или шорткодов CPM, но не при обработке REST-запросов (см. `docs/03-base-manager.md`).

## Граница ответственности (важно)

Ядро не занимается отображением. UI отвечает за:

- парсинг и отображение контента сущностей (Markdown / HTML / шорткоды) — см. `docs/core/контент-сущностей.md`;
- рендер картинок, миниатюр, превью и иконок типов файлов (получает объект `Attachment` из ядра и выводит его) — см. `docs/core/attachment.md`;
- отображение графиков (например, активностей в проекте) средствами **Mermaid** (рендеринг Mermaid в модуле фронтенда включён по умолчанию);
- в редакторе должны использоваться Mermaid-блоки по образу и подобию Obsidian;
- отображение ошибок/запрета доступа (ядра сигнализирует через исключения `AccessDeniedException`).
