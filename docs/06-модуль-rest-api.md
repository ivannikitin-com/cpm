# Модуль REST API

> **Детальные спецификации модуля перенесены в каталог `docs/rest-api/`** (README, архитектура, маршруты, схемы, права и ошибки, загрузка файлов, аутентификация, тесты, открытые вопросы). Этот файл — краткий обзор места модуля в архитектуре и точка входа.

## Место в архитектуре

REST API — модуль CPM v3 для интеграции системы с внешними сервисами и с собственным UI (UI — это React-приложение, которое работает через REST API).

- Менеджер модуля: `\CPM\v3\REST\REST_API_Manager`, файл `CPM_PLUGIN_DIR/classes/rest_api/rest_api_manager.php`.
- Создаётся в классе `Plugin` по хуку `init`.
- Известное требование: ядро не рендерит интерфейс, REST-контроллеры сущностей данных предназначены для интеграции с внешними сервисами.

## Связанные требования из ядра

- Контроллеры должны работать с сущностями ядра через `Core_Manager` (фабричные методы `load_list()` / `create()`) и уважать права (декораторы, `AccessDeniedException`). См. `docs/core/`.
- Вложение `Attachment` отдаётся через REST-прокси: `GET /cpm/v1/attachment/{id}/file` с проверкой прав и `403/404` при отсутствии доступа. Подробнее: `docs/core/attachment.md`, `docs/rest-api/загрузка-файлов.md`.
- Ответы и коды ошибок: верхний слой REST перехватывает `CPM_Exception` и превращает его в понятный пользователю ответ (`403` для `AccessDeniedException`, `404` для отсутствующей сущности). См. `docs/core/ошибки.md`, `docs/rest-api/права-и-ошибки.md`.
