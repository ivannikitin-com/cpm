# Роли пользователей CPM v3: семантика

Документ описывает **смысл и семантику ролей пользователей** (`manager`, `co_worker`, `client`, `administrator`), их исторический контекст в старых версиях CPM и значение в v3.

> Таблица прав по типам сущностей, маппинг «роль → декоратор» и формат хранения участников находятся в **нормативном** документе `права-и-роли.md`. Этот документ их не дублирует, а описывает только значения ролей.

## В старой версии CPM

В предыдущих версиях CPM не использовала стандартные для WordPress роли, а позволяла для каждого проекта назначать свои роли для пользователей.

## Роли старых версий

- `manager` — менеджер проекта, может выполнять любые действия.
- `co_worker` — исполнитель, не может создавать новые списки задач, но может создавать новые задачи, отмечать выполненные задачи и всё комментировать.
- `client` — то же, что и `co_worker`, но не имеет доступа к «закрытым» задачам (в старой версии задачи с замочком — только для сотрудников).

В старых версиях роли хранятся в таблице `wp_cpm_user_role` (префикс может быть любым):

```
in_cpm_user_role {
	bigint    ID PK
	bigint    project_id FK
	bigint    user_id FK
	varchar   role
	varchar   component
}
```

- **ID** — первичный ключ с автоинкрементом.
- **project_id** — идентификатор проекта, к которому относится роль.
- **user_id** — идентификатор пользователя.
- **role** — название роли (например, `manager`, `co_worker`, `client`).
- **component** — компонент системы, к которому применяется роль. **НЕ ИСПОЛЬЗУЕТСЯ!**

## В новой версии CPM v3

Сохранено деление на три роли в проекте:

- `manager` — полные права в проекте: редактировать проект, архивировать его, переводить в выполненное состояние, менять координатора и участников, выполнять любые операции над сущностями проекта. **Единственное ограничение** — не может удалить сам проект (удаление проекта доступно только `administrator`).
- `co_worker` — любые операции с сущностями проекта, за исключением удаления любой сущности.
- `client` — следующие права:
  - чтение и запись для: задач, комментариев к любой сущности;
  - только чтение для сущностей: обсуждения, списки задач;
  - запрет доступа к сущностям: файлы, вехи, активности.
- Добавляется новая виртуальная роль `administrator`, которая фактически проверяется по роли WordPress `administrator`. Если пользователь — администратор WordPress, никакие проверки прав и ограничений в CPM не производятся. Администратору разрешены любые операции в CPM.
