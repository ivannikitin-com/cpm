# Класс Team

Класс `\CPM\v3\Core\Team` хранит информацию об участниках сущностей. **Не проверяет права** — более того, смысл списка участников у разных сущностей разный:

- у проекта это определение доступа;
- у списка задач это участники задачи по умолчанию;
- у задачи это ответственные (кому отправлять оповещение).

Проверки прав доступа на уровне проекта реализуются декораторами, которые используют класс `Team` для получения списка пользователей к текущей сущности.

> **Важно**: `_team` хранит список пользователей в мета-поле не в сериализованном виде, а в виде **одной строки**. Подробнее — `права-и-роли.md`.

Класс хранит список пользователей, представленных экземплярами `User`.

## Свойства

| Свойство | Тип | Назначение |
| -------- | --- | ---------- |
| `members` | array | Ассоциативный массив `user_id => role` |

## Методы

| Метод | Назначение |
| ----- | ---------- |
| конструктор `__construct($members)` | Получает строку `members` в формате, описанном в `права-и-роли.md`, и формирует массив `members` |
| `add($user_id, $role)` | Добавляет в массив ID пользователя и роль |
| `remove($user_id)` | Удаляет из массива `members` элемент `user_id`. Если не найден — ничего не делает |
| `get_members()` | Возвращает строку `members` в формате `права-и-роли.md`. Используется только для сохранения данных в БД в мета-поле `_team` |

## Получение отдельного пользователя

Просто обращаемся к свойству `members`. Например, как получить роль пользователя:

```php
$user_id   = 123;
$user_role = ( array_key_exists( $user_id, $team->members ) )
	? $team->members[ $user_id ]
	: ACL::NO_ROLE;
```

> Используется именно `array_key_exists()` (проверка ключа ассоциативного массива), а не `in_array()`.
