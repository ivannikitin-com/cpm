# Класс Base_Decorator

Абстрактный базовый класс для всех декораторов сущностей CPM (`\CPM\v3\Core\Base_Decorator`). Реализует базовую логику проверки прав на основе ролей пользователей для большинства типов сущностей.

Декоратор **оборачивает** объект сущности и управляет доступом к его методам и свойствам в зависимости от прав текущего пользователя. Он реализует интерфейс `IEntity` (как и сущность), поэтому снаружи декоратор неотличим от сущности.

## Назначение

- Проверяет права текущего пользователя на операцию (чтение/модификацию) для обёрнутой сущности.
- С помощью магических методов реализует доступ к **любому методу и свойству** объекта, который обернул: запросы на чтение проходят напрямую, запросы на изменение — только если разрешено.

## Свойства

| Свойство | Тип | Назначение |
| -------- | --- | ---------- |
| `entity` | IEntity | Обёрнутый объект сущности |

## Методы

| Метод | Назначение |
| ----- | ---------- |
| конструктор `__construct($entity, $args)` | Сохраняет ссылку на обёрнутую сущность. `$args` — аргументы, переданные фабричным методом `Core_Manager` |
| `get_type()` | Возвращает тип сущности, делегируя обёрнутой сущности |
| `get_project()` | Делегирует обёрнутой сущности |
| `save()` | Сохраняет обёрнутую сущность в БД, предварительно проверив права на модификацию |
| `delete($is_recursion)` | Удаляет обёрнутую сущность, предварительно проверив права на модификацию |
| `can_modify()` (protected, abstract) | Определяет, разрешена ли текущему пользователю модификация этой сущности. Перекрывается в конкретных декораторах |
| `__call()`, `__get()`, `__set()` | Магические методы, делегируют обращение к обёрнутой сущности. Записи свойств разрешены только если `can_modify()` возвращает `true` |

## Реализация проверки прав

Роль пользователя для сущности вычисляется методом `ACL::get_role( $entity )`. Базовый декоратор использует роль и таблицу прав из `права-и-роли.md`, чтобы решить, разрешено ли действие.

Пример базовой логики `save()`:

```php
public function save() {
	if ( $this->can_modify() ) {
		$this->entity->save();
	}
	else {
		// Действие запрещено: выбрасываем AccessDeniedException
		throw new AccessDeniedException( ... );
	}
}
```

> **Модель запрета (решение)**: ядро выбрасывает `AccessDeniedException` и **не выполняет** операцию. Молчаливый no-op не используется. Как это показывается пользователю, решает UI / REST (см. `ошибки.md`).

## Конкретные декораторы

| Декоратор | Спецификация | Поведение |
| --------- | ------------ | --------- |
| `ReadOnly_Decorator` | `read-only-decorator.md` | Запрещает любые модификации |
| `Modify_Decorator` | `modify-decorator.md` | Разрешает любые модификации |
| `ModifyOwn_Decorator` | `modify-own-decorator.md` | Разрешает модификацию только своих сущностей |
| `Stuff_Decorator` | `stuff-decorator.md` | Модификация только для сотрудников (`MANAGER` / `CO_WORKER`) |

## Примечание: более ранний вариант декоратора

В источниках существует более ранний черновик базового декоратора (2026-02-19) с иной моделью: свойства `current_user_role` и `ROLE_NOT_DEFINED`, методы `prepare()`, `check_save()`, `check_delete()`, `post_update()` и исключение `OperationNotPermitException`. Эта модель **считается устаревшей** и заменена описанной выше моделью `can_modify()` + `AccessDeniedException`. В реализации v3 применяется актуальная модель (актуальная также на 2026-08-21 в `ошибки.md`).
