# Выборка сущностей SQL запросом

Для максимальной производительности и уменьшения нагрузки на MySQL выборка списка сущностей (проектов, задач и т.п.) в `Core_Manager::load_list($type, $args)` осуществляется **одним большим запросом** для каждого типа сущностей. Эти запросы сохраняются как статичное свойство `SQL` для каждого класса сущности.

## Прототипы SQL — не продакшн-код

Все SQL-запросы в документации ядра — это **примеры/прототипы**, иллюстрирующие, как одним запросом выбрать сущности сразу со всеми нужными полями и фильтрами (в том числе по участнику проекта). Они намеренно упрощены для наглядности.

В реальном коде необходимо соблюдать нормальный подход:

- **Параметризованные запросы.** Значения фильтров (ID пользователя, ID проекта, slug и т.п.) подставляются только через `$wpdb->prepare()`, никогда не вставляются конкатенацией в строку запроса.
- **Правильные имена таблиц.** Вместо жёстко прописанных `in_posts` / `in_postmeta` / `in_cpm_user_role` в коде используются `$wpdb->posts`, `$wpdb->postmeta` и т.п., чтобы запрос корректно работал при любом префиксе WordPress.
- **Фильтр по пользователю формируется динамически.** В примерах условие записано как `( is_admin OR team LIKE '%"277"%' )`, где `is_admin` — **параметр запроса**, принимающий значение `true` для пользователя с ролью WordPress `administrator`. При `is_admin = true` условие всегда истинно, и фильтрация по участнику не выполняется (администратору доступны все сущности). Для остальных пользователей `is_admin = false`, а в `team LIKE ...` подставляется ID текущего пользователя через `$wpdb->prepare()`.

## Фильтры и выборка сущностей

### Выборка сущностей, доступных пользователю

Любому пользователю доступны только те сущности, которые входят в проекты, членом которых является этот пользователь. Исключение — пользователь с ролью WordPress `administrator`, которому доступны все сущности.

### Другие фильтры

Другие фильтры подставляются в запрос в блок WHERE или HAVING, например:

```sql
...
HAVING
	TRUE
	-- Здесь могут быть любые дополнительные фильтры, например:
	AND project_id = 6583     -- Проект 6583
	AND slug = 'my-project'   -- Проект со слагом my-project
```

Отличительная черта блока — явное `HAVING TRUE` или `WHERE TRUE`.
