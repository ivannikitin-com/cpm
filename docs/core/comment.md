# Класс Comment

Класс сущности «Комментарий» (`\CPM\v3\Core\Comment`). Отражает комментарий к любой сущности CPM (задаче, обсуждению, списку задач и т.п.). Наследует `Entity`.

> **Статус**: черновик. Структура построена на основе `Entity`, `Project_Entity` и таблицы прав. Реальные CPT/поля/SQL-запрос требуют решения и уточнения. См. `открытые-вопросы.md`.

## Особенность хранения

В отличие от большинства сущностей, комментарий **не хранится как Custom Post Type**, а использует штатный механизм комментариев WordPress (таблица `comments`). Это следует из базового `Entity`:

- `delete_entity()` «может быть перекрыто потомками, например, для удаления комментария»;
- `save()` и `get_wp_args()` «для других типов сущностей (например, для комментариев) реализация должна быть переопределена».

Соответственно, у `Comment` **нет** статичного свойства `CPT`, а вместо SQL-выборки используется стандартный API комментариев WordPress (`get_comments()` / `wp_insert_comment()` / `wp_delete_comment()`).

## Связь с проектом

Комментарий принадлежит некоторой сущности (поле `parent`), поэтому `get_project()` определяется через проект родительской сущности. Для получения проекта используется цепочка `parent` → проект.

> Подтверждено реальной БД: комментарии привязаны не только к задачам, но и к `post`, `cpm_message`, `cpm_task_list`, `cpm_docs`. `get_project()` комментария должен уметь проходить цепочку для любого из этих типов.

## Права доступа

| Роль | Право |
| ---- | ----- |
| MANAGER | modify_own |
| CO_WORKER | modify_own |
| CLIENT | modify_own |
| ADMINISTRATOR | полный доступ |

Декоратор: `ModifyOwn_Decorator` — пользователь может модифицировать только свои комментарии (автор == текущий пользователь).

## Свойства

| Свойство | Тип | Соответствие полю `comments` |
| -------- | --- | ----------------------------- |
| `content` | string | `comment_content` — текст комментария (см. `контент-сущностей.md`) |
| `author` | int | `user_id` — автор комментария |
| `created_at` | string | `comment_date` — дата создания |
| `parent` | int | `comment_post_ID` — сущность, к которой относится комментарий |
| `files` | int[] | `commentmeta._files` — сериализованный массив ID вложений (см. `attachment.md`) |

## Чтение через ядро (решение)

Чтение комментариев выполняется через `Core_Manager::load_list( 'comment', $args )`, который делегирует в `Comment::query_rows()` (штатный `WP_Comment_Query` / `get_comments()`, тип `comment`, статус `approve`):

- Фильтры: `parent` (комментарии сущности), `id` (один комментарий).
- Пагинация/сортировка: `per_page`/`page`/`offset`, `orderby`/`order` — транслируются в аргументы `WP_Comment_Query`. Свойство `orderby` маппится в поле WP (`id → comment_ID`, `created_at → comment_date`, `author → user_id`, `parent → comment_post_ID`, `content → comment_content`); по умолчанию `comment_date_gmt ASC`.
- Общее число комментариев — `Comment::query_count()` (`count => true`) через `Core_Manager::count_list( 'comment', $args )`.
