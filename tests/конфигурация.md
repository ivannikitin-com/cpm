# Конфигурация тестирования

Спецификация подключения PHPUnit и настройки окружения. Реализуется при первом создании кода (см. `bootstrap.php`, `phpunit.xml.dist`, `phpunit-integration.xml.dist` в этой папке).

## Composer (dev-зависимости)

В корне проекта создаётся `composer.json` **только для dev-зависимостей** — рантайм-код плагина намеренно не использует автозагрузчик (см. `docs/03-base-manager.md`, `docs/09-стандарты-кодирования.md`), поэтому секция `autoload` не нужна.

```json
{
	"name": "ivannikitin/cpm",
	"description": "CPM v3 — WordPress-плагин управления проектами",
	"type": "wordpress-plugin",
	"license": "GPL-2.0-or-later",
	"require": {},
	"require-dev": {
		"phpunit/phpunit": "^9.6",
		"10up/wp_mock": "^0.4.2",
		"wp-phpunit/wp-phpunit": "^6.6"
	},
	"config": {
		"sort-packages": true,
		"allow-plugins": false
	},
	"scripts": {
		"test": "phpunit",
		"test:unit": "phpunit",
		"test:integration": "phpunit -c phpunit-integration.xml.dist"
	}
}
```

> **Важно про версии**: PHPUnit и wp-phpunit должны соответствовать **версии PHP в Docker-контейнере WordPress**. Указанные версии корректны для PHP 7.4–8.3. Если стенд на другой версии PHP — версии зависимостей пересматриваются до `composer install`.
>
> Совместимость `10up/wp_mock` с выбранной версией PHPUnit проверить при первой установке (см. `стандарты-тестов.md`).

## Структура конфигов

| Файл | Назначение |
| ---- | ---------- |
| `phpunit.xml.dist` | Юнит-уровень: bootstrap `tests/bootstrap.php`, suite `tests/unit` |
| `phpunit-integration.xml.dist` | Интеграционный уровень: bootstrap `tests/integration/bootstrap.php`, suite `tests/integration` |

PHPUnit не поддерживает разный bootstrap для разных testsuite в одном конфиге, поэтому используется **два конфига**.

## Окружение интеграционных тестов

### Тестовая БД

- Имя БД: `cpm_test` (не путать с рабочей БД стенда).
- Создаётся в MySQL-контейнере Docker при старте стенда (прописать в `docker-compose` при его создании, например командой `MYSQL_DATABASE` для отдельного сервиса или init-скриптом).
- Каждый тест работает в транзакции: WP test suite откатывает изменения после каждого теста — данные фикстур не «протекают» между тестами.
- **Никогда** не запускать интеграционные тесты против рабочей БД.

### Переменные окружения (для wp-phpunit)

Тест-каркас WordPress читает настройки из переменных окружения:

| Переменная | Значение (пример) |
| ---------- | ----------------- |
| `WP_TESTS_DIR` | путь к тест-либе: `vendor/wp-phpunit/wp-phpunit` |
| `WP_TESTS_DB_NAME` | `cpm_test` |
| `WP_TESTS_DB_USER` | пользователь MySQL стенда |
| `WP_TESTS_DB_PASS` | пароль MySQL стенда |
| `WP_TESTS_DB_HOST` | хост MySQL (внутри сети Docker — имя сервиса, например `db`) |
| `WP_TESTS_DOMAIN` | домен тестового WP, например `cpm.test` |

### Прогон в Docker

Интеграционные тесты выполняются **внутри контейнера WordPress** (там есть PHP, MySQL, WP core):

```bash
docker compose exec wp composer install
docker compose exec -e WP_TESTS_DIR=/var/www/html/wp-content/plugins/cpm/vendor/wp-phpunit/wp-phpunit \
	-e WP_TESTS_DB_NAME=cpm_test -e WP_TESTS_DB_HOST=db \
	wp vendor/bin/phpunit -c phpunit-integration.xml.dist
```

Точная команда будет зафиксирована после создания `docker-compose`.

### ABSPATH для тест-каркаса

Тест-либа wp-phpunit требует установленный WordPress core. В контейнере он уже есть; при необходимости указать `ABSPATH` через env (см. документацию wp-phpunit). Этот момент уточняется при первой настройке на стенде.

## Запуск

```bash
# юнит
vendor/bin/phpunit

# интеграция
WP_TESTS_DIR=... vendor/bin/phpunit -c phpunit-integration.xml.dist
```
