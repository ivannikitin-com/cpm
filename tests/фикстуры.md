# Данные-фикстуры

Форматы данных для тестов. Юнит-тесты используют PHP-массивы/строки напрямую; интеграционные — создают записи в тестовой БД через фабрики.

> **Важно про `.gitignore`**: в корне проекта игнорируются `*.sql` (см. `.gitignore`). Поэтому фикстуры НЕ хранятся как `.sql`-файлы — только как PHP-данные/фабрики. Если в будущем понадобится SQL-фикстура, добавить в `.gitignore` исключение (например, `!tests/**/*.sql`).

## Новый формат (v3)

### `_team` — участники сущности

Строка `"user_id":role,...` в мета-поле `_team`:

```
"12":manager,"15":co_worker,"22":co_worker,"33":client
```

- `user_id` — число в двойных кавычках (12 ≠ 112).
- Роли `administrator` и `none` в БД не сохраняются.

### Мета-поля сущностей

Полный справочник — `docs/core/мета-поля.md`. Ключевые для фикстур:

| Сущность | Мета-поля |
| -------- | --------- |
| Project | `_cpm_coordinator` (int), `_project_active` (`yes`/`no`) |
| Task | `_start`, `_due`, `_completed` (`1`/`0`), `_completed_on`, `_completed_by`, `_task_privacy` (`yes`/`no`) |
| Task_List | `_milestone` (ID или `-1`) |
| Message | `_message_privacy` (`yes`/`no`), `_milestone` (ID или `0`), `_files` (сериализованный массив) |
| Note | `_doc_type` (`_custom_doc` / `_google_doc`), `_project_uploaded` |
| Milestone | `_due`, `_completed` |
| Attachment | `_project` (ID), `_parent` (ID), `_wp_attached_file` (путь) |
| Comment | `commentmeta._files` (сериализованный массив) |
| Все, кроме Comment | `_thumbnail_id` (int, `0` = нет), `_team` |

## Старый формат (обратная совместимость)

Используется для проверки бесшовного чтения старых данных (см. `docs/core/совместимость.md`, `docs/core/проверка-старых-данных.md`).

### Таблица `in_cpm_user_role` (старые роли в проектах)

| Поле | Пример |
| ---- | ------ |
| `ID` | 1 |
| `project_id` | 6583 |
| `user_id` | 277 |
| `role` | `manager` |
| `component` | пусто (не используется) |

Реальный пример из проверки (проект 6583), формат строки team после `GROUP_CONCAT`:

```
"1":manager,"277":manager,"220":manager,"35":manager,...
```

### `_assigned` (старые участники задач)

Несколько записей `postmeta` на задачу (по одной на пользователя), не сериализованная строка. Пример (задача 6936):

```
"23":"","406":""
```

SQL собирает их через `GROUP_CONCAT` и конвертирует в формат team (см. `docs/core/task.md`).

### Комментарии и вложения

- Вложения: записи `attachment` (mime, title, status='inherit'), мета `_project`, `_wp_attached_file`; связь с комментарием — через `commentmeta._files`.
- `_files` у комментария — сериализованный массив ID. Пустой массив `a:0:{}` — **нормальное состояние** (132K из 150K комментариев), обрабатывается как «файлов нет».
- Активность: комментарии с `comment_type='cpm_activity'`, текст может содержать шорткоды (выводятся как есть).

## Фабрики (интеграционные тесты)

Фикстуры создаются фабричными методами в `tests/integration/factories/` (по мере появления кода). Общие принципы:

- Фабрики используют штатные функции WordPress (`wp_insert_post`, `add_post_meta`, `wp_insert_comment`, `wp_insert_user`), а не прямые `$wpdb`-вставки — так фикстуры соответствуют тому, как данные создаёт реальный код.
- Для старого формата допустимы прямые вставки через `$wpdb` (таблицы `in_cpm_user_role` и мета `_assigned` штатными функциями не создаются) — но только в тестовой БД.
- Каждый интеграционный тест изолирован: WP test suite откатывает транзакцию после теста.
