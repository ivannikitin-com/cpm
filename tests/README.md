# Тестирование CPM v3

Спецификация стратегии тестирования плагина. Тесты пишутся параллельно с кодом: агент, реализующий класс из `docs/`, обязан добавить тесты на него по матрице покрытия (`покрытие.md`).

## Цель

Проверять, что реализация соответствует спецификациям в `docs/`, и не дать регрессиям сломать уже согласованную логику. Ключевые зоны риска:

- **права доступа** (ACL, декораторы, таблица прав) — ошибка здесь = утечка/потеря доступа;
- **обратная совместимость чтения** (старый формат `in_cpm_user_role` / `_assigned` → новый `_team`) — бесшовный переход без миграции;
- **SQL-выборка** (один запрос на тип, фильтр `is_admin OR team LIKE ...`);
- **хуки и кэш** (`cpm_core_entity_*`, отложенный `flush()` при рекурсии).

## Стратегия: два уровня

Плагин на ~90% состоит из вызовов WordPress-функций и зависит от реальной схемы БД, поэтому одного уровня тестов недостаточно.

### Уровень 1 — юнит-тесты (PHPUnit + WP_Mock)

- Быстрые, **без БД**. Гоняются на каждый коммит.
- WordPress-функции (`wp_insert_post`, `get_current_user_id`, `$wpdb`, `do_action`, `wp_cache_*` и т.п.) мокаются через **WP_Mock**.
- Покрывают: чистую логику (`Team`, `ACL`, декораторы) и логику с моками (`Entity::save()/delete()`, `Core_Manager`).
- Каталог: `tests/unit/`. Конфиг: `phpunit.xml.dist`.

### Уровень 2 — интеграционные тесты (WP test suite / реальный WP в Docker)

- Медленные, требуют **отдельной тестовой БД** (`cpm_test`). Гоняются на стенде в Docker.
- Используют стандартный PHPUnit-каркас WordPress (`WP_UnitTestCase`), поставляемый пакетом `wp-phpunit/wp-phpunit`.
- Покрывают: SQL-выборку каждого типа, обратную совместимость чтения, реальные хуки, регистрацию CPT, права на уровне выборки.
- Каталог: `tests/integration/`. Конфиг: `phpunit-integration.xml.dist`.

> **Почему юнитами не ограничиться**: главная ценность проекта — бесшовный переход со старых данных. Приоритет `COALESCE()`, конвертация `_assigned` в team, чтение комментариев/вложений проверяются только на живой БД с фикстурами в старом формате.

## Требования к окружению

- PHP + Composer (версия PHP в Docker-контейнере WP определяет версии зависимостей, см. `конфигурация.md`).
- Для интеграционных тестов — MySQL с БД `cpm_test` (создаётся в MySQL-контейнере) и установленный WordPress (уже есть в контейнере).

## Быстрый старт (на стенде)

```bash
# Установка dev-зависимостей (PHPUnit, WP_Mock, тест-каркас WP)
composer install

# Юнит-тесты (без БД)
vendor/bin/phpunit

# Интеграционные тесты (нужны WP_TESTS_DIR и БД cpm_test)
WP_TESTS_DIR=... vendor/bin/phpunit -c phpunit-integration.xml.dist
```

Точные команды для Docker — в `конфигурация.md`.

## Карта папки

```
tests/
├── README.md                    ← этот файл
├── конфигурация.md              ← composer.json, окружение, тестовая БД
├── покрытие.md                  ← матрица «класс → что и где тестируем»
├── фикстуры.md                  ← форматы данных (старый/новый) для фикстур
├── стандарты-тестов.md          ← конвенции именования и паттерны WP_Mock
├── phpunit.xml.dist             ← конфиг юнит-тестов
├── bootstrap.php                ← загрузчик юнит-тестов (WP_Mock)
├── phpunit-integration.xml.dist ← конфиг интеграционных тестов
├── integration/
│   └── bootstrap.php            ← загрузчик интеграционных тестов (WP test suite)
├── unit/                        ← юнит-тесты (создаются вместе с кодом)
└── integration/                 ← интеграционные тесты (создаются вместе с кодом)
```

## Границы тестирования

- **Не тестируется** рендеринг UI (отдельный фронтенд-проект), внешние сервисы (AI, OpenRouter), конфигурация сервера (nginx/.htaccess для `uploads/cpm/`).
- Кэш тестируется на уровне логики сброса (`flush()` вызывается в нужный момент), а не на уровне реального memcached/Redis.
- «Голые» SQL-прототипы из `docs/` не исполняются как есть (таблицы `in_*` не существуют); проверяется их продакшн-аналог через `$wpdb` в интеграционных тестах.

## Связь со спецификациями

Матрица покрытия ссылается на документы `docs/core/`. При изменении спецификации в `docs/` соответствующие тесты обновляются в том же изменении.
